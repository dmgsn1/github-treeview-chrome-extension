How to create a token

Fine-grained token: read-only, but it covers one owner (your account or one organisation).

  1. github.com → your avatar → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token (open).
  2. Resource owner: the organisation whose repositories you work in.
  3. Repository access: All repositories.
  4. Permissions → Repository permissions: Actions, Commit statuses, Contents and Issues → Read-only (statuses, contents and Actions are what the PR check states and the Lift holds safety check read); Pull requests → Read and write if you want Lift holds (it removes the hold:operator label), otherwise Read-only. Metadata is added automatically. There is no Checks permission for these tokens; the panel works without it.
  5. Generate token, copy it, paste it above and press Save.

If the organisation requires approval for fine-grained tokens, the token sees nothing there until an organisation owner approves it (organisation → Settings → Personal access tokens → Pending requests).

Classic token: covers every owner at once; its repo scope allows writes everywhere. The only write this extension makes is removing hold:operator when you lift holds.

  1. Same path, then Tokens (classic) → Generate new token (classic) (open with the scopes ticked).
  2. Scopes: repo and read:org.
  3. For an organisation with SAML single sign-on: next to the new token, Configure SSO → Authorize.

Leave blank to cover every owner the token can read: your account, your organisations, and anything already in the tree. Enterprise Cloud organisations count as ordinary organisations. GitHub Enterprise Server (a company's own GitHub host) is not supported.

Updating: replace the files in the folder Chrome loads this extension from (chrome://extensions → GitHub Tree → Details → Source), then press ↻ on its card. Unzipping into a new folder leaves Chrome on the old build. .
